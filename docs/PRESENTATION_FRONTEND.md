# UniWiki-AI 프론트엔드 기술 및 구현 방식

## 1. 프론트엔드의 역할

프론트엔드는 위키 탐색, 질문과 답변, AI 챗봇, 데이터 지도, 관리자 기능을 하나의 웹 UI로 제공한다. 모든 데이터 변경은 백엔드 REST API를 통해 처리하며, LLM API 키나 DB 정보는 브라우저에 노출하지 않는다.

```text
사용자
→ React 화면
→ Axios API 모듈
→ Spring Boot 백엔드
```

## 2. 사용 기술

| 구분 | 기술 | 사용 목적 |
|---|---|---|
| UI | React 19 | 컴포넌트 기반 화면 구성 |
| 빌드 도구 | Vite 8 | 개발 서버와 프로덕션 빌드 |
| 라우팅 | React Router DOM 7 | SPA 페이지 이동과 권한 라우트 |
| HTTP | Axios | 백엔드 API 요청과 공통 인터셉터 |
| 상태 공유 | React Context | 로그인 사용자 상태 공유 |
| 스타일 | CSS, 디자인 토큰 | 화면별 스타일과 반응형 UI |
| 배포 설정 | Vercel | 정적 빌드와 SPA 경로 재작성 |

Redux나 별도 서버 상태 라이브러리를 추가하지 않고, 현재 규모에서 필요한 인증 상태는 Context로, 페이지 데이터는 각 화면의 React 상태로 관리한다.

## 3. 화면 구조

```text
main.jsx
├── AppErrorBoundary
├── BrowserRouter
├── AuthProvider
└── App
    └── MainLayout
        ├── Header
        ├── Page
        └── Footer
```

전역 오류 경계가 렌더링 오류를 처리하고, `AuthProvider`가 로그인 사용자를 공유한다. 공통 레이아웃 안에서 페이지별 콘텐츠만 교체된다.

## 4. 주요 라우트

| 경로 | 기능 |
|---|---|
| `/` | 서비스 소개와 주요 콘텐츠 |
| `/wiki` | 공식 위키 목록·검색·정렬 |
| `/wiki/community` | 함께 만든 위키 목록 |
| `/wiki/:wikiPostId` | 위키 상세와 출처 확인 |
| `/questions` | 질문 게시판 목록 |
| `/questions/:questionId` | 질문·답변·추천·채택 |
| `/chatbot` | 위키 기반 AI 질문 |
| `/visualization` | 수집량과 신뢰도 데이터 지도 |
| `/mypage` | 로그인 사용자 정보 |
| `/admin` | 관리자 위키 선정과 현황 관리 |

작성·수정 페이지는 `ProtectedRoute`로 보호하고, 관리자 화면은 `AdminRoute`에서 역할을 추가로 확인한다.

## 5. API 모듈화

`src/api.js`에 Axios 인스턴스와 도메인별 API 함수를 모아 페이지가 URL과 인증 처리를 반복하지 않도록 했다.

```text
Page Component
→ api.getQuestions() / api.askAi() 등 호출
→ Axios 공통 인스턴스
→ 요청 인터셉터에서 JWT 추가
→ 백엔드 호출
→ 응답 또는 공통 오류 변환
```

주요 공통 처리:

- `VITE_API_BASE_URL`로 환경별 API 주소 설정
- 기본 요청 제한 시간 45초
- 저장된 JWT가 있으면 Authorization 헤더 자동 추가
- `401 Unauthorized` 응답 시 잘못된 인증 정보 제거
- 백엔드 오류 형식을 사용자 메시지로 통일
- `204 No Content` 응답은 `null`로 정규화

## 6. 로그인 상태 관리

로그인 성공 시 JWT와 최소 사용자 정보를 브라우저 저장소에 보관한다.

```text
로그인 응답
→ JWT: uniwiki-token
→ 사용자: uniwiki-user
→ 인증 변경 이벤트 발생
→ AuthContext 갱신
→ Header와 보호 라우트 즉시 반영
```

사용자 객체에는 ID, 이메일, 닉네임, 역할만 저장한다. 비밀번호나 서버 비밀키는 저장하지 않는다. 새로고침 시에는 저장된 사용자 정보를 먼저 복원하고, 백엔드의 `/api/users/me`로 실제 세션 유효성을 확인한다.

## 7. 위키 UI

- 최신 위키 목록 표시
- 2026년부터 과거 연도 순으로 정렬
- 제목과 본문 검색
- 카테고리 및 출처 유형 필터
- 페이지 번호를 한 번에 10개씩 표시
- 공식 위키와 함께 만든 위키 분리
- 위키 상세에서 원문 출처 제공
- 로그인 사용자 대상 위키 추천과 작성·수정 기능
- 작성 버튼은 데스크톱에서 우측 일반 버튼 크기, 모바일에서 좌측 정렬로 표시
- 카테고리 API의 레거시 인코딩 항목은 정상 한글·정상 카테고리 ID로 정규화해 표시

고정 콘텐츠와 일반 위키 목록을 분리해 공식 출처 안내, 수강편람, 함께 만든 위키 진입점을 먼저 제공한다.

## 8. 질문 게시판 UI

- 게시물과 답변 목록
- 추천 수 표시와 추천/취소
- `답변 대기`와 `답변 완료` 상태 구분
- 질문 작성자의 답변 채택
- 관리자의 질문·답변 위키 선정
- 채택 또는 선정 결과를 함께 만든 위키로 연결

외부 커뮤니티에서 수집된 자료도 별도 메뉴로 노출하지 않고 질문 게시판의 일반 게시물·답변 형태로 표현한다.

## 9. AI 챗봇 UI

프론트엔드는 질문만 백엔드에 전달한다.

```text
사용자 질문 입력
→ POST /api/ai/answers
→ 로딩 상태 표시
→ 답변 출력
→ 출처 위키 링크 출력
```

브라우저가 AI 서비스나 OpenAI를 직접 호출하지 않기 때문에 API 키가 노출되지 않는다. 답변과 함께 받은 출처를 클릭하면 실제 위키 상세 페이지로 이동한다.

## 10. 데이터 지도

데이터 지도는 단순히 파일 개수를 보여주는 화면에서, 자료의 신뢰성과 AI 활용 가능성을 설명하는 화면으로 확장됐다.

- 공식 자료와 커뮤니티 자료 구분
- 카테고리별 수집 위키 수
- 출처 등록 여부
- 원문과 첨부파일 처리 여부
- 최신성 및 벡터 반영 상태
- 부족한 데이터 영역 식별

이를 통해 데이터 양과 신뢰성을 함께 확인할 수 있다.

## 11. 스타일링 방식

별도 UI 프레임워크 없이 CSS를 기능별 파일로 분리했다.

```text
tokens.css       색상·간격 등 공통 토큰
layout.css       헤더·푸터·공통 배치
wiki.css         위키 화면
questions.css    질문 게시판
chatbot.css      AI 채팅
admin.css        관리자 화면
responsive.css   모바일·작은 화면 대응
```

기존 기능을 유지하면서 새 UI 디자인을 연결하기 위해 공통 디자인 토큰과 화면별 스타일을 분리했다.

## 12. 개발과 배포

로컬 개발에서는 Vite 프록시가 `/api` 요청을 `http://localhost:8080`으로 전달한다.

```bash
npm run dev
npm run build
npm run preview
```

운영 빌드는 `dist` 폴더에 생성된다. React Router의 직접 경로 접속이 404가 되지 않도록 Vercel에서 모든 화면 경로를 `index.html`로 재작성한다.

## 13. 발표용 핵심 요약

> 프론트엔드는 React 19와 Vite로 구현한 SPA입니다. React Router로 공개·로그인·관리자 라우트를 구분하고, Axios 인터셉터가 JWT와 오류 처리를 공통으로 담당합니다. 위키, 질문 게시판, 함께 만든 위키, AI 챗봇, 데이터 지도를 하나의 서비스 흐름으로 연결했으며, AI 키는 프론트에 두지 않고 모든 AI 요청을 백엔드를 통해 전달합니다.

## 14. 시연 순서 제안

1. 위키 검색과 연도·카테고리 필터
2. 질문 게시물과 답변 완료 상태 확인
3. 로그인 전후 작성 버튼과 보호 라우트 비교
4. 관리자 화면에서 함께 만든 위키 선정
5. 챗봇 질문 후 출처 링크 이동
6. 데이터 지도에서 카테고리별 수집량과 신뢰도 확인
